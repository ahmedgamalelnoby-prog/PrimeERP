# Stage 8 — POS E2E & Operational Completion

Base: verified Stage 7 financial/reservation hardening head.

## Implemented invariants

- Cashier must be active, non-deleted, and in the authenticated tenant before opening a POS session.
- POS order variants must belong to the selected item and company; items with active variants require an explicit variant.
- POS accounting is atomic: the configured POS journal must support auto-posting so an order cannot finalize with physical stock posted but the sale journal left unposted.
- POS session close reconciles the supplied closing total against posted POS payments for the session.
- Optional method-level EOD reconciliation verifies cash/card/bank/other independently.
- Reservation service now uses the canonical ProductVariant.is_active field.
- Existing Stage 7 migration remains the anchor; EOD fields are additive to the existing hardening migration.
- Duplicate model-registry imports were removed.

## Transaction path

Outlet → Device → Cashier Session → Draft Order → Variant/Recipe validation → Inventory issue/recipe consumption → POS sale journal → Payment settlement journal → EOD reconciliation.

## Explicit boundary

This stage does not modify the frozen release/2026-09-21-rc1 branch or rewrite prior migrations. Changes are downstream and additive.
